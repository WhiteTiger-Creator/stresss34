The metrics-rollup compiler at `/app/workflow/metric_rollup.py` ships in a broken state: it produces unsafe responder queues that must be corrected. The primary task is to repair the compiler so it again computes the responder rollup the change-advisory board signed off. It keeps its interface `--input PATH --output-dir PATH` (defaults `/app/data/samples.json` and `/app/output`) and writes `rollup_summary.json`, `gap_windows.json` and compact `alert_queue.jsonl`. It must be idempotent and must keep working on a different sample input of the same shape. `/app/docs/rollup_contract.json` is the output contract — source paths, schemas, exact key sets, identifier payloads and checksum encodings — and the output must match it exactly.

How the compile is meant to behave is not in the contract. The change-advisory board settled it, and `/app/sample/rollup_review_log.md` is the record: normalization, dedupe, interval and overlap semantics, policy resolution and its sparse-field fallbacks, attenuation, the debt ledger, scoring, priority and ordering are all MET-ticketed entries in there. Where two entries disagree, the later dated decision governs. Every rollup value must be derived from the input samples, the fixed source files and the board's rulings — never hardcoded and never copied from any precomputed or expected-output file. Leave the frozen reference snapshot `/app/workflow/.metric_rollup.original` unchanged.

The same failed rollout also left the responder host in a degraded state, and restoring it is part of the deliverable. `/app/docs/deployment_runbook.md` defines the required host state: a dedicated service account with no interactive shell; the operator wrapper at `/usr/local/bin/rollup-metrics`; the compile lock under `/var/lock`; the cron schedule that runs the compile under the service account; the output and log directories under `/app/output` and `/var/log/metrics-rollup` with correct ownership and modes; the log-rotation drop-in; and cleanup of the stale lock and the unrotated leftover the crashed run left behind. Bring each of these to the state the runbook specifies so the scheduled compile both runs and rotates as the service account rather than as root.
